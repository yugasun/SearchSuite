# ADR-0001：TypeScript v0.1 架构基线

- 状态：Accepted
- 日期：2026-08-22
- 决策者：SearchSuite maintainers

## Context

SearchSuite 需要将 `dsh-web-search` 中已验证的多 Provider 搜索能力抽取为可被任意 Node.js 应用使用的 SDK。原方案使用 Python，但项目希望更自然地融入 TypeScript/dsh 生态，同时保持核心框架无关。

外部 Provider API 差异很大且持续变化。若 v0.1 同时实现 Provider 兼容、路由、dsh 插件和 operational features，公共接口难以稳定。

## Decision

1. v0.1 发布单一 npm 包 `searchsuite`，不发布 dsh 插件。
2. 使用 TypeScript strict，最低 Node.js 24，纯 ESM，不支持 CommonJS。
3. 使用 Node 原生 fetch/AbortSignal，发布包零 runtime dependency。
4. Public API 为 `await client.search({ engine: 'provider:engine', ... })`，不提供 `asearch` 或 `close`。
5. 首发 Baidu、Doubao、Tavily、Exa、Serper，并采用现有 `dsh-web-search` 已验证 engine。
6. `SearchEngine` 使用 template-literal union；`providerOptions` 根据 engine 条件推导并运行时验证。
7. 公共响应保持 JSON-friendly；日期使用 ISO string，raw 使用安全 `unknown`。
8. 内置 Provider 使用显式动态 import Registry，不扫描目录，不承诺第三方注册 API。
9. Client 支持注入 fetch、timeout、caller AbortSignal、compatibility mode 和 warning hook。
10. Adapter 不实现 route、fallback、retry、multi-key、cache、fusion 或 dsh 行为。

## Rationale

- TypeScript 与现有 dsh Provider 实现同语言，未来复用不需要 Python bridge。
- Node.js 24 提供成熟原生 fetch/AbortSignal，零 runtime dependency 可降低安装、冲突和供应链成本。
- ESM-only 符合目标生态，避免为低价值 CommonJS 兼容增加双构建和导出复杂度。
- Client 类提供配置、惰性 Provider 缓存和统一策略；单一 async 方法符合 JavaScript 网络 API 语义。
- engine 感知 options 让统一接口不牺牲 Provider 特性，也发挥 TypeScript 的核心价值。
- 显式 Registry 提供确定导入、安全边界和 bundle 可分析性。
- dsh 集成延后确保 SearchSuite 是可被 dsh 使用的底层库，而不是反向依赖 Harness 的插件代码。

## Alternatives considered

### 保持 Python SDK

拒绝。它适合 Python Agent/RAG 生态，但会增加 `dsh-web-search` 的进程/协议桥接成本，不符合当前主要集成方向。

### TypeScript 同时发布 ESM 和 CommonJS

拒绝。目标 Node LTS 与 dsh 均支持 ESM；双格式会增加 package exports、测试、构建和 singleton 行为风险，收益有限。

### 单包内提供 dsh 子路径或第二个插件包

v0.1 不采用。会引入 `@deepseek-ai/*` peer dependency、插件 metadata 和额外版本协同。未来可由独立 adapter 或现有 `dsh-web-search` 消费核心 SDK。

### 使用 Provider 官方 SDK

v0.1 不采用。五家 Search API 都可通过 HTTP 实现；直接使用原生 fetch 能保持统一取消、错误、测试和零依赖。

### 使用无类型 `Record<string, unknown>` options

拒绝。它实现容易但损失 TypeScript SDK 的主要价值。条件类型与 runtime allowlist 增加少量维护成本，换取可靠开发体验。

### v0.1 实现 Router/fallback/retry

拒绝。请求次数、成本和错误语义会改变，且需要稳定 capability/health/eval 数据，应作为上层独立决策。

## Consequences

正面：API 小、类型强、零依赖、易嵌入 Node/dsh 生态、Adapter 边界清晰。

代价：Node 24 以下和 CommonJS 用户无法使用；新增 Provider 需要同步修改类型和 Registry；runtime options 校验需要手写；v0.1 调用方自行选择 Provider 和处理 retry/fallback。

## Follow-up

- Milestone 0 验证 timeout 与 caller signal 的竞态实现。
- 三个 Provider 后评估最小 HTTP helper，禁止提前建立复杂基类。
- v0.2 若开放第三方 Provider，新增 ADR 评估 module augmentation、generic Client 或 entry point registry。
- 任何自动 retry/fallback 必须通过新 ADR 说明幂等性、默认请求次数、成本与可观测性。
